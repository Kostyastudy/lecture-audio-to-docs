# 两次实战记录（给未来的自己）

## 案例 A：学习经验分享会（2026-10-26）

- 输入：`录音 1.m4a`，46.9 MB，2h20m14s，现场多人、含问答。
- 课件：无。
- 交付：38 页文字稿（约 3.4 万字）、15 页总结（约 1.1 万字）、原始转写 txt。

时间线：

| 时间 | 事件 |
|---|---|
| 10:53 | 开始；第一次写文件就报 ACL `SetNamedSecurityInfoW failed (Win32 5)`，用 `diagnose-windows-sandbox-acl` 修复 |
| 11:00 | 环境无 whisper/av/ffmpeg；pip 装 faster-whisper 1.2.1 + av 19，av 19 与 fw 不兼容，降到 av 13.1.0 |
| 11:06 | large-v3 下载 3 GB；3 分钟样本 0.32x → 全片约 7 小时，放弃 |
| 11:20 | 换 turbo（1.6 GB），单进程 2.2x；4 路并行 2.73x |
| 11:30 | 8 路 × 2 线程启动，部分进程 OOM 崩；改 3 路 |
| 11:49 | turbo 正式跑 8 块 × 17 分钟，beam 5，3 路 × 4 线程 |
| 19:36 | 8 块才跑完：单块 27,500 秒（约 7.6 小时），整体 8 小时。**核心教训：大块 + beam5 + 多进程会病态变慢** |
| 19:36 | 写 4 个 clean_part、summary、md2docx；渲染发现括号注释太密，polish 后重建 3 次 |

结果：文字稿质量可用，但成本极高。

## 案例 B：2026 级本科培养方案解读（2026-10-28）

- 输入：`标准录音 3.mp3`，109 MB，45m28s；PPT 导出 PDF 31 页。
- 交付：10 页文字稿（约 7.5k 字）、13 页总结（约 9.4k 字，13 张表）。

时间线：

| 时间 | 事件 |
|---|---|
| 19:44 | 读上次脚本与产出，确认格式；加载 pdf / office-docx 技能 |
| 19:47 | Whisper 自动下载卡住；hf-mirror 308、huggingface TLS 断流；改用 ModelScope 分块下载 |
| 19:55 | 1.54 GB / 383 秒 / 3.8 MB/s 下完 |
| 19:49 | ffmpeg 缺失；PyAV 对该 MP3 报 `Invalid data`；装 imageio-ffmpeg 转 wav |
| 19:48 | pypdf 提取中文 UnicodeEncodeError；换 pymupdf，31 页 6322 字 |
| 20:03 | 单进程全片 0.9x，放弃；改 chunk |
| 20:04 | 4 块 × 11 分钟，4 进程 × 4 线程，beam5，12 分钟无输出；py-spy 看到卡在 `generate_with_fallback`；全部杀掉 |
| 20:12 | 6 块 × 7.6 分钟，6 进程 × 3 线程，beam1；worker 崩（内存），再降到 3 块 |
| 20:25 | 改为 60 秒 chunk、chunk_worker 常驻模型；46 块，2–6 个 worker 反复调参 |
| 20:26–20:56 | 46 块跑完，约 30 分钟；期间并行读 PPT、写 notes_ppt、写总结初稿 |
| 20:58 | md→docx；渲染 10 页 / 13 页 |
| 20:59 | 修表格跨页、页脚、标题重复；清理中间文件；present |

关键差异：60 秒块 + 常驻模型 + beam1 + 3–6 worker，45 分钟音频 25–30 分钟转完。相比案例 A 提速约 16 倍。

## 复用时的默认判断

- 音频 < 15 分钟：`asr_full.py` 单进程即可，省去切块。
- 音频 15 分钟–1 小时：60 秒块，3 worker × 5 线程，约 0.5x 音频时长。
- 音频 > 1 小时：同一配置，但先告诉用户 ETA；超过 3 小时考虑分段交付。
- 有课件：先读课件再转写，术语表能省掉一半校对。
- 无课件：文字稿更重要，总结要更保守，少下判断。
